# Introduction

첫 번째 글에서 IP 주소 몇 개를 나열한 간단한 Inventory로 Ansible의 기본 동작을 확인했습니다. 하지만 실제 환경에서는 수십 개 이상의 호스트를 관리해야 하며, 각 호스트는 서로 다른 역할과 설정을 가집니다. 웹 서버, 데이터베이스 서버, 로드 밸런서가 각각 다른 설정을 필요로 하고, 개발 환경과 프로덕션 환경은 분리되어야 합니다. 이러한 복잡성을 효과적으로 관리하기 위해서는 Inventory의 기능들을 이해하고 활용해야 합니다.

# Understanding Inventory Structure

Ansible Inventory는 관리 대상 호스트의 목록과 설정을 담은 파일입니다. 기본 위치는 `/etc/ansible/hosts`이지만 프로젝트별로 별도의 Inventory 파일을 만드는 것이 권장됩니다.

![blog ui](/assets/img/posts/2026-01-18-ansible2/inventory.png) *https://kimalarm.tistory.com/78*

Inventory는 INI와 YAML 두 가지 형식을 지원합니다. Kubespray를 포함한 많은 프로젝트들이 INI 형식을 사용하지만, 이 글에서는 YAML 형식을 사용합니다.

가장 간단한 형태는 호스트를 한 줄에 하나씩 나열하는 것입니다.

```yaml
192.168.10.10
192.168.10.11
web-server.example.com
```

호스트를 역할별로 그룹화하면 특정 그룹에만 작업을 수행할 수 있습니다. 그룹명은 대괄호로 감쌉니다.

```yaml
[webservers]
web1.example.com
web2.example.com

[databases]
db1.example.com
db2.example.com
```

한 호스트는 여러 그룹에 동시에 속할 수 있습니다.

```yaml
[webservers]
web1.example.com

[production]
web1.example.com
db1.example.com

[staging]
web2.example.com
```

중첩 그룹을 만들 때는 `:children` 키워드를 사용합니다.

```yaml
[webservers]
web1.example.com
web2.example.com

[databases]
db1.example.com

[production:children]
webservers
databases
```

반복적인 호스트 정의를 간소화할 수 있습니다.

```yaml
[webservers]
web[1:10].example.com        # web1, web2, ..., web10

[databases]
db[01:20].example.com         # db01, db02, ..., db20 (zero-padded)

[dns_servers]
dns[a:d].example.com          # dnsa, dnsb, dnsc, dnsd (alphabetical)

[compute_nodes]
192.168.4.[0:255]             # 192.168.4.0 to 192.168.4.255 (IP range)
```

# Organizing Hosts with Groups

[Ansible 공식 문서](https://docs.ansible.com/projects/ansible/latest/getting_started/get_started_inventory.html#tips-for-building-inventories)에서 그룹을 구성할 때 What, Where, When 세 가지 관점을 고려할 것을 권장합니다.

- **What**: 호스트의 역할
- **Where**: 리전, 데이터센터 등 물리적/논리적 위치
- **When**: dev,prod와 같은 생명주기 단계

또한 그룹명은 아래와 같은 Naming Conventions를 가집니다.

- 공백, 하이픈 사용 금지
- 숫자로 시작하지 않기 (e.g. `19th_floor` → `floor_19`)
- 대소문자 구분됨
- 의미가 명확한 이름 사용

# Variables

변수를 사용하면 호스트별로 다른 설정을 적용할 수 있습니다.

## Host Variables

호스트명 옆에 변수를 정의합니다. `key=value` 형식을 사용하며, 공백으로 구분합니다.

```yaml
[webservers]
web1 ansible_host=192.168.10.10 ansible_port=22 ansible_user=ubuntu
web2 ansible_host=192.168.10.11 ansible_port=2222 ansible_user=centos
```

## Group Variables

그룹 전체에 공통 변수를 적용할 때는 `[groupname:vars]` 섹션을 사용합니다.

```yaml
[webservers]
web1 ansible_host=192.168.10.10
web2 ansible_host=192.168.10.11

[webservers:vars]
ansible_user=ubuntu
http_port=80
```

모든 호스트에 적용되는 변수는 `[all:vars]`에 정의합니다.

```yaml
[all:vars]
ansible_python_interpreter=/usr/bin/python3
```

## Using group_vars and host_vars

변수가 많아지면 Inventory 파일이 복잡해집니다. 이때 group_vars와 host_vars 디렉터리를 사용하면 변수를 별도 파일로 분리할 수 있습니다.

`inventory/group_vars/all.yml`: 모든 호스트에 적용

```yaml
---
ansible_python_interpreter: /usr/bin/python3
```

`inventory/group_vars/webservers.yml`: webservers 그룹에만 적용

```yaml
---
http_port: 80
https_port: 443
max_clients: 200
```

`inventory/host_vars/web1.example.com.yml` - 특정 호스트만 적용

```yaml
---
ansible_host: 192.168.10.10
max_clients: 300
```

이제 Inventory 파일은 호스트와 그룹 구조만 정의하고, 변수는 별도 파일로 관리합니다.

## Variable Precedence

위와 같이 Ansible은 여러 위치에서 변수를 정의할 수 있으며, 같은 이름의 변수가 여러 곳에 정의된 경우 명확한 우선순위 규칙에 따라 최종 값이 결정됩니다. Inventory 내에서의 변수 우선순위는 다음과 같습니다.

1. **Host Variables (host_vars)**: 특정 호스트에만 적용되는 변수로 가장 높은 우선순위를 가집니다.
2. **Group Variables (group_vars)**: 그룹에 속한 모든 호스트에 적용되며, 호스트 변수가 없을 때 사용됩니다.
3. **All Group Variables**: 모든 호스트에 기본값으로 적용되는 변수로 가장 낮은 우선순위를 가집니다.

이를 확인하기 위해 아래와 같이 Inventory를 구성합니다.

```yaml
[all:vars]
http_port=80

[webservers]
web1
web2

[db]
db1

[webservers:vars]
http_port=8080
```

그리고 추가로 `host_vars/web1.yml`에 다음과 같이 변수를 정의합니다.

```yaml
http_port: 9090
```

위와 같은 구성시 http_port에 대해 호스트별로 아래와 같은 결과가 나타나게 됩니다.

- web1의 http_port: 9090(host_vars 우선)
- web2의 http_port: 8080(group_vars 적용)
- db1의 http_port: 80(all group_vars 적용)

# Dynamic Inventory

정적 Inventory는 모든 호스트를 수동으로 관리합니다. 클라우드 환경에서는 Auto Scaling으로 인스턴스가 자주 생성되고 삭제되므로 정적 Inventory 유지가 어렵습니다.

Dynamic Inventory는 Cloud Provider API를 실시간으로 호출하여 인스턴스 목록을 가져옵니다. Ansible은 두 가지 방법을 지원합니다.

1. **Inventory Script**(Legacy)
2. **Inventory Plugin(Recommended)**

## AWS EC2 Dynamic Inventory

AWS 환경에서 가장 많이 사용되는 aws_ec2 플러그인을 실습합니다.

### Prerequisites

이를 위해서는 필수 패키지가 설치되어야 합니다.

```bash
pip install boto3 botocore

ansible-galaxy collection install amazon.aws
```

### Authentication

AWS 인증은 다양한 방법을 지원합니다.

- **Environment Variables**: `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`
- **AWS Profile**: `~/.aws/credentials`의 정의된 프로필 사용 (`profile` 파라미터)
- **IAM Instance Profile**: EC2에 attached된 IAM 역할 자동 사용
- **AWS SSO**: SSO 로그인 후, 프로필 통해 사용

### Configuration

Inventory Plugin을 사용하여 AWS EC2 인스턴스를 동적으로 관리합니다.이 때의 Inventory 파일명은 `aws_ec2.yml` 또는 `aws_ec2.yaml`로 정의되어야 합니다.

> The inventory file is a YAML configuration file and must end with aws_ec2.{yml |
 yaml}

```yaml
plugin: amazon.aws.aws_ec2
regions:
  - ap-northeast-2
filters:
  instance-state-name: running
```

필터를 사용하여 특정 조건의 인스턴스만 Inventory에 포함할 수 있습니다.

`keyed_groups`를 사용하면 EC2 태그를 기반으로 자동으로 그룹을 생성할 수 있습니다.

```yaml
plugin: amazon.aws.aws_ec2
regions:
  - ap-northeast-2
filters:
  instance-state-name: running
keyed_groups:
  # 모든 태그로 그룹 생성: tag_<태그키>_<태그값>` 형식의 그룹으로 만듭니다.
  - prefix: tag
    key: tags
  # 특정 태그값으로 그룹 생성: e.g., Environment_dev, Environment_prod
  - key: tags.Environment
    separator: ''
  # 인스턴스 유형별 그룹 e.g., instance_type_t3_small
  - prefix: instance_type
    key: instance_type
```

# Practice

## Creating Inventory

학습한 내용을 종합하여 Inventory를 구성합니다.

```bash
mkdir -p inventory/group_vars
touch inventory/hosts
```

```bash
cat <<EOT > inventory
[web]
tnode1
tnode2

[db]
tnode3

[all:children]
web
db
EOT
```

## Project Configuration

프로젝트 디렉터리에 `ansible.cfg`를 만들어 일관된 환경을 유지합니다.

```bash
cat <<EOT > ansible.cfg
[defaults]
inventory = ./inventory
remote_user = root
host_key_checking = False

[privilege_escalation]
become = True
become_method = sudo
become_user = root
become_ask_pass = False
EOT
```

- inventory: 기본 Inventory 파일 위치
- remote_user: 원격 접속 사용자 이름, 이름을 지정하지 않으면 현재 사용자 이름으로 지정됨
- host_key_checking: SSH 호스트 키 검증 (False로 설정 시 처음 접속할 때 자동 승인)
- become: 권한 상승 여부
- become_method: sudo, su 등 권한 상승 방법
- become_ask_pass: sudo, su 등 권한 상승 시 패스워드 입력 여부

설정 파일 구성 시, `-i`옵션을 사용하지 않아도 inventory 파일 위치를 명시하였기 때문에 정의된 호스트 정보를 확인할 수 있습니다.
